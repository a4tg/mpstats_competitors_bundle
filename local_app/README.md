# Ozon SKU Lab — локальная первая версия

Запуск: двойной щелчок по `run_local_app.bat` в корне проекта. Откроется http://127.0.0.1:8765. Окно запуска должно оставаться открытым; для остановки нажмите Ctrl+C. Нужны Python и зависимости из существующего requirements.txt. Если порт занят: `py local_app/server.py --port 8766`.

## Входы

1. Список товаров: TXT со SKU по одному в строке; CSV/XLSX с заголовком `SKU` и/или `Артикул` в первой строке. Подходит существующий `Request_loader/SKU.txt` или подготовленный файл запросов: повторяющиеся SKU объединяются. Числовые SKU храните как текст, без округления.
2. ABC-XYZ книга с листами текущего образца. Основной источник метрик — `Сводная`, связь SKU/артикул — `Окупаемость (нужно обновлять)`. При иной структуре понадобится адаптация сопоставления колонок. `Ozon Product ID` и идентификатор связки не подменяют SKU.
3. Необязательно: подготовленная таблица запросов (Артикул, SKU, Запрос, Частота из выгрузки) и результат существующего сборщика конкурентов.

Количество товаров не фиксировано. Повторы SKU удаляются. Конфликт SKU/артикула и неоднозначный поиск по артикулу выводятся как ошибки сопоставления. Программа не выбирает одну из нескольких строк сводки молча.

## Результат

Архив содержит data.json с исходными строками и источниками, metrics.csv, список ограничений и задание для нейросети. Значения Excel читаются из сохранённого кэша; программа не пересчитывает формулы. Перед загрузкой сохраните актуальную книгу в Excel. Ошибки в основных метриках заменяются на null с пометкой; в исходных строках сохраняются для аудита.

Все загрузки и результаты хранятся в `local_app/runs/<id>/`. Для истории каждый импорт создаёт новый каталог. Пакет не содержит профиля браузера или cookies. Данные не отправляются нейросети автоматически.

## MPSTATS

Если приложена подготовленная таблица запросов, после импорта доступна кнопка сбора конкурентов. Она запускает существующий `mpstats_competitors.py` через адаптер, отбирая только выбранные SKU. Chrome откроется для входа в MPSTATS. Используется прежний профиль `mpstats_profile`, отдельные результат и SQLite-кэш внутри запуска. Не запускайте старый сборщик одновременно с приложением.

Собственные SKU из всей приложенной таблицы запросов исключаются из кандидатов. Исключение полного портфеля брендов и проверка продуктовой эквивалентности пока не реализованы. После сбора приложение заново формирует пакет. Неполное покрытие/HTTP-ошибки останавливают включение нового результата; можно повторить сбор с кэшем. Журнал доступен из интерфейса.

## Границы первой версии

- Полная диагностика второй книги не воспроизводится: нет исходника `62_products_review.xlsx` и формализованных порогов.
- Выгрузка сырых поисковых запросов из карточек и их тематическая классификация пока остаются отдельным этапом. Для сбора конкурентов нужен уже подготовленный файл запросов.
- Нет автоматического сравнения периодов, обработки кластерной логистики и исключения собственных брендов.
- При неизвестном периоде данные явно отмечаются как требующие проверки. Пустые значения не означают ноль.
- Интерфейс работает только на 127.0.0.1; запуск и загрузка защищены от запросов с посторонних страниц токеном и проверкой Host/Origin.

## Проверка

`py -m unittest discover -s local_app/tests -v`

Тесты проверяют сопоставление идентификаторов, неоднозначные связи, структуру существующей книги и экспорт пакета. Сетевой сбор требует отдельного входа пользователя в MPSTATS.
